# Seguridad de autenticación y autorización

- Nunca agregues un campo "rol" ni "usuarioId" a un DTO que el cliente pueda
  enviar. El rol y el dueño de un recurso se asignan en el servidor, nunca
  vienen del body de la petición.
- Toda contraseña se cifra con bcrypt (factor de costo 10 o más). Nunca la
  guardes ni la registres en texto plano, ni en logs ni en consola.
- El JWT se firma solo con el algoritmo por defecto de @nestjs/jwt. Nunca
  sugieras deshabilitar la verificación de la firma.
- Todo endpoint que modifique o exponga datos debe pasar por JwtAuthGuard, y
  si aplica una restricción de rol, también por RolesGuard.
- Los mensajes de error de login y registro nunca deben revelar si un email
  existe o no en la base de datos.
- Nunca imprimas JWT_SECRET, DATABASE_URL, un access_token completo ni
  contraseñas en console.log ni en mensajes de error.
- La configuración sensible (JWT_SECRET, DATABASE_URL) se lee de variables de
  entorno; nunca la escribas literal en el código ni la subas a GitHub.

AuthService completoCrear · src/auth/auth.service.ts · TypeScript
Crearsrc/auth/auth.service.ts
import {
  ConflictException,
  Injectable,
  UnauthorizedException,
} from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import * as bcrypt from 'bcrypt';
import { PrismaService } from '../prisma/prisma.service';
import { RegisterDto } from './dto/register.dto';
import { LoginDto } from './dto/login.dto';

@Injectable()
export class AuthService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly jwtService: JwtService,
  ) {}

  async register(dto: RegisterDto) {
    const existente = await this.prisma.usuario.findUnique({
      where: { email: dto.email },
    });
    if (existente) {
      throw new ConflictException('El email ya está registrado');
    }

    const hash = await bcrypt.hash(dto.password, 10);

    const usuario = await this.prisma.usuario.create({
      data: { nombre: dto.nombre, email: dto.email, password: hash },
    });

    return { id: usuario.id, nombre: usuario.nombre, email: usuario.email };
  }

  async login(dto: LoginDto) {
    const usuario = await this.prisma.usuario.findUnique({
      where: { email: dto.email },
    });
    if (!usuario) {
      throw new UnauthorizedException('Credenciales inválidas');
    }

    const passwordOk = await bcrypt.compare(dto.password, usuario.password);
    if (!passwordOk) {
      throw new UnauthorizedException('Credenciales inválidas');
    }

    const payload = {
      sub: usuario.id,
      email: usuario.email,
      rol: usuario.rol,
    };
    const access_token = await this.jwtService.signAsync(payload);

    return { access_token };
  }
}

import { Injectable, UnauthorizedException } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';
import { Rol } from '../generated/prisma/client';

type JwtPayload = { sub: number; email: string; rol: Rol };

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor() {
    const secret = process.env.JWT_SECRET;
    if (!secret) {
      throw new UnauthorizedException('JWT_SECRET no está definida');
    }
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: secret,
    });
  }

  validate(payload: JwtPayload) {
    return { id: payload.sub, email: payload.email, rol: payload.rol };
  }
}

RolesGuard completoCrear · src/auth/roles.guard.ts · TypeScript
Crearsrc/auth/roles.guard.ts
import {
  CanActivate,
  ExecutionContext,
  ForbiddenException,
  Injectable,
} from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { Rol } from '../generated/prisma/client';
import { Roles } from './roles.decorator';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const rolesRequeridos = this.reflector.get(Roles, context.getHandler());

    if (!rolesRequeridos) {
      return true;
    }

    const request = context.switchToHttp().getRequest();
    const usuario = request.user as { rol: Rol };

    if (!rolesRequeridos.includes(usuario.rol)) {
      throw new ForbiddenException('No tienes permiso para realizar esta acción');
    }

    return true;
  }
}

05 · Reglas de negocio

Tareas con ownership y arranque de producción

El token identifica al dueño; el servicio impide leer o modificar tareas ajenas; main.ts escucha el puerto del entorno.

Predice el flujo

Si una tarea existe pero pertenece a otro usuario, ¿la respuesta correcta es 404 o 403?

Ver criterio

En esta implementación: 403. La API encontró el recurso, pero el usuario autenticado no tiene permiso. Si no existe, responde 404.

Ownership correcto

  • usuarioId sale del token
  • listar filtra por dueño
  • editar y borrar verifican primero

Diseño inseguro

  • usuarioId llega en el body
  • listar devuelve todo
  • update confía solo en el id
!

Dos líneas deciden el deploy

main.ts debe usar process.env.PORT y escuchar en 0.0.0.0. Un puerto fijo o localhost interno dejan el servicio fuera del tráfico público.

Crearsrc/tareas/tareas.service.ts
import {
  ForbiddenException,
  Injectable,
  NotFoundException,
} from '@nestjs/common';
import { PrismaService } from '../prisma/prisma.service';
import { CrearTareaDto } from './dto/crear-tarea.dto';
import { ActualizarTareaDto } from './dto/actualizar-tarea.dto';

@Injectable()
export class TareasService {
  constructor(private readonly prisma: PrismaService) {}

  crear(dto: CrearTareaDto, usuarioId: number) {
    return this.prisma.tarea.create({
      data: {
        titulo: dto.titulo,
        descripcion: dto.descripcion,
        prioridad: dto.prioridad,
        usuarioId,
      },
    });
  }

  obtenerMias(usuarioId: number) {
    return this.prisma.tarea.findMany({
      where: { usuarioId },
      orderBy: { id: 'asc' },
    });
  }

  obtenerTodasAdmin() {
    return this.prisma.tarea.findMany({
      include: {
        usuario: { select: { id: true, nombre: true, email: true } },
      },
      orderBy: { id: 'asc' },
    });
  }

  async obtenerUna(id: number, usuarioId: number) {
    const tarea = await this.prisma.tarea.findUnique({ where: { id } });

    if (!tarea) {
      throw new NotFoundException('La tarea no existe');
    }

    if (tarea.usuarioId !== usuarioId) {
      throw new ForbiddenException('Esta tarea no es tuya');
    }

    return tarea;
  }

  async actualizar(id: number, dto: ActualizarTareaDto, usuarioId: number) {
    await this.obtenerUna(id, usuarioId);
    return this.prisma.tarea.update({ where: { id }, data: dto });
  }

  async eliminar(id: number, usuarioId: number) {
    await this.obtenerUna(id, usuarioId);
    return this.prisma.tarea.delete({ where: { id } });
  }
}

  @UseGuards(RolesGuard)

  obtenerTodasAdmin() {

  }

  obtenerUna(
    @Param('id', ParseIntPipe) id: number,
    @UsuarioActual() usuario: { id: number },
  ) {
    return this.tareasService.obtenerUna(id, usuario.id);
  }

  actualizar(
    @Param('id', ParseIntPipe) id: number,
    @Body() dto: ActualizarTareaDto,
    @UsuarioActual() usuario: { id: number },
  ) {

  eliminar(

import {
  ArgumentsHost,
  Catch,
  ExceptionFilter,
  HttpException,
  HttpStatus,
} from '@nestjs/common';
import { Request, Response } from 'express';

@Catch()
export class HttpExceptionFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    const esExcepcionHttp = exception instanceof HttpException;
    const statusCode = esExcepcionHttp
      ? exception.getStatus()
      : HttpStatus.INTERNAL_SERVER_ERROR;

    let mensaje: string | string[] = 'Error interno del servidor';
    if (esExcepcionHttp) {
      const cuerpo = exception.getResponse();
      mensaje = typeof cuerpo === 'string' ? cuerpo : (cuerpo as any).message;
    } else {
      console.error(exception);
    }

    response.status(statusCode).json({
      statusCode,
      timestamp: new Date().toISOString(),
      path: request.url,
      message: mensaje,
    });
  }
}

08 · Concepto central 2

Docker elimina el “depende de mi máquina”

Una imagen describe el paquete; un contenedor es una instancia de ese paquete en ejecución.

Para pensar

¿Por qué instalar Node y dependencias a mano en cada servidor no garantiza el mismo resultado?

Ver respuesta

Porque cada instalación puede terminar con versiones, sistema y configuración diferentes.

La imagen fija base, dependencias, código, compilación y arranque en una receta repetible.

Imagen

  • plantilla inmutable
  • se construye con docker build
  • se puede distribuir

Contenedor

  • instancia en ejecución
  • se inicia con docker run
  • recibe configuración externa
i

Modelo mental

El Dockerfile es la receta, la imagen es el paquete sellado y el contenedor es ese paquete encendido. Render construye y ejecuta la misma receta.
