01 · El problema

El frontend necesita un contrato

El historial crece. Consultarlo y entender sus errores debe ser predecible.

Para pensar

La API ya reconoce al usuario. ¿Por qué el frontend sigue teniendo dificultades para integrar el historial?

Ver respuesta

La identidad y los permisos no resuelven la calidad de los datos ni el formato de los errores. Necesitamos filtros, paginación y una respuesta de error común.

La petición de producto

El historial debe filtrar por tipo y rango de fechas, con paginación. Si llega una página negativa o una fecha inválida, el frontend necesita interpretar la respuesta con el mismo contrato.

El filtro de Prisma solo atiende sus errores. La validación y los fallos inesperados tienen sus propias respuestas. Hoy coordinamos esas piezas.

05 · Transformar y validar

La aduana de la petición

Un Pipe actúa antes de entregar el argumento al método del controlador.

Para pensar

La URL contiene ?pagina=2. ¿Qué debe ocurrir antes de calcular la paginación?

Ver respuesta

Convertir ese texto a número y validar que sea un entero permitido. En las propiedades de este DTO usamos @Type(() => Number) junto con transform: true.

Dos trabajos, una frontera

Transformar cambia la forma o el tipo del dato. Validar comprueba reglas y lanza una excepción si no se cumplen. Como una aduana, el Pipe prepara o rechaza la entrada antes del negocio.

ParseIntPipe resuelve un :id. Para cinco campos y una regla entre fechas, usamos un DTO con el ValidationPipe global. El Service mantiene la lógica de consulta.

import { Type } from 'class-transformer';
import {
  IsDateString,
  IsEnum,
  IsInt,
  IsOptional,
  Max,
  Min,
  Validate,
  ValidationArguments,
  ValidatorConstraint,
  ValidatorConstraintInterface,
} from 'class-validator';
import { ApiPropertyOptional } from '@nestjs/swagger';
import { TipoTransaccionDto } from './crear-transaccion.dto';

@ValidatorConstraint({ name: 'RangoDeFechasValido', async: false })
class RangoDeFechasValidoConstraint implements ValidatorConstraintInterface {
  validate(hasta: string | undefined, args: ValidationArguments) {
    const dto = args.object as FiltrarTransaccionesDto;
    if (!dto.desde || !hasta) {
      return true;
    }
    return new Date(hasta) >= new Date(dto.desde);
  }

  defaultMessage() {
    return 'La fecha "hasta" no puede ser anterior a la fecha "desde"';
  }
}

export class FiltrarTransaccionesDto {
  @ApiPropertyOptional({ enum: TipoTransaccionDto })
  @IsOptional()
  @IsEnum(TipoTransaccionDto, { message: 'El tipo debe ser INGRESO o GASTO' })
  tipo?: TipoTransaccionDto;

  @ApiPropertyOptional({ example: '2026-01-01' })
  @IsOptional()
  @IsDateString({}, { message: 'La fecha "desde" debe tener formato AAAA-MM-DD' })
  desde?: string;

  @ApiPropertyOptional({ example: '2026-01-31' })
  @IsOptional()
  @IsDateString({}, { message: 'La fecha "hasta" debe tener formato AAAA-MM-DD' })
  @Validate(RangoDeFechasValidoConstraint)
  hasta?: string;

  @ApiPropertyOptional({ example: 1, default: 1 })
  @IsOptional()
  @Type(() => Number)
  @IsInt({ message: 'La página debe ser un número entero' })
  @Min(1, { message: 'La página debe ser al menos 1' })
  pagina?: number = 1;

  @ApiPropertyOptional({ example: 10, default: 10 })
  @IsOptional()
  @Type(() => Number)
  @IsInt({ message: 'El límite debe ser un número entero' })
  @Min(1, { message: 'El límite debe ser al menos 1' })
  @Max(50, { message: 'El límite no puede superar 50' })
  limite?: number = 10;
}

Qué representa la fecha

El mensaje usa AAAA-MM-DD y los ejemplos son fechas simples. @IsDateString() valida ISO 8601; no limita por sí solo la entrada exclusivamente a ese formato corto.

07 · Consultar y paginar

El filtro nunca pierde al dueño

Prisma consulta la página y cuenta el mismo conjunto de registros.

Detecta la responsabilidad

¿Dónde debe permanecer usuarioId al añadir filtros opcionales?

Comprobar razonamiento

Dentro del where base, siempre presente en obtenerMias. Los filtros opcionales no sustituyen la restricción por propietario.

01

Construir el conjunto de consulta

El where conserva usuarioId y añade tipo y fechas solo cuando llegan. gte y lte incluyen sus instantes límite.

02

Obtener una página y su total

skip indica cuántos registros saltar; take limita la página. findMany y count reciben el mismo where. Promise.all espera ambas operaciones; no crea por sí solo una transacción.

import {
  ForbiddenException,
  Injectable,
  NotFoundException,
} from '@nestjs/common';
import { Prisma } from '../generated/prisma/client';
import { PrismaService } from '../prisma/prisma.service';
import { CrearTransaccionDto } from './dto/crear-transaccion.dto';
import { ActualizarTransaccionDto } from './dto/actualizar-transaccion.dto';
import { FiltrarTransaccionesDto } from './dto/filtrar-transacciones.dto';

@Injectable()
export class TransaccionesService {
  constructor(private readonly prisma: PrismaService) {}

  crear(dto: CrearTransaccionDto, usuarioId: number) {
    return this.prisma.transaccion.create({
      data: {
        descripcion: dto.descripcion,
        monto: dto.monto,
        tipo: dto.tipo,
        categoriaId: dto.categoriaId,
        usuarioId,
      },
      include: { categoria: true },
    });
  }

  async obtenerMias(usuarioId: number, filtros: FiltrarTransaccionesDto) {
    const { tipo, desde, hasta, pagina = 1, limite = 10 } = filtros;

    const where: Prisma.TransaccionWhereInput = {
      usuarioId,
      ...(tipo && { tipo }),
      ...(desde || hasta
        ? {
            fecha: {
              ...(desde && { gte: new Date(desde) }),
              ...(hasta && { lte: new Date(hasta) }),
            },
          }
        : {}),
    };

    const [datos, total] = await Promise.all([
      this.prisma.transaccion.findMany({
        where,
        include: { categoria: true },
        orderBy: { fecha: 'desc' },
        skip: (pagina - 1) * limite,
        take: limite,
      }),
      this.prisma.transaccion.count({ where }),
    ]);

    return {
      datos,
      meta: { pagina, limite, total, totalPaginas: Math.ceil(total / limite) },
    };
  }

  obtenerTodasAdmin() {
    return this.prisma.transaccion.findMany({
      include: {
        categoria: true,
        usuario: { select: { id: true, nombre: true, email: true } },
      },
      orderBy: { id: 'asc' },
    });
  }

  async obtenerUna(id: number, usuarioId: number) {
    const transaccion = await this.prisma.transaccion.findUnique({
      where: { id },
      include: { categoria: true },
    });

    if (!transaccion) {
      throw new NotFoundException('La transacción no existe');
    }

    if (transaccion.usuarioId !== usuarioId) {
      throw new ForbiddenException('Esta transacción no es tuya');
    }

    return transaccion;
  }

  async actualizar(
    id: number,
    dto: ActualizarTransaccionDto,
    usuarioId: number,
  ) {
    await this.obtenerUna(id, usuarioId);
    return this.prisma.transaccion.update({
      where: { id },
      data: dto,
      include: { categoria: true },
    });
  }

  async eliminar(id: number, usuarioId: number) {
    await this.obtenerUna(id, usuarioId);
    return this.prisma.transaccion.delete({ where: { id } });
  }
}
i

Alcance exacto de «hasta»

El código conserva lte: new Date(hasta). Con 2026-01-31, el límite es el inicio de ese día en UTC, no todo el día. Tenlo presente al interpretar resultados con hora.

10 · Errores HTTP

Una respuesta predecible

El filtro decide qué recibe el cliente cuando se lanza una excepción.

Decide

¿Qué debe conservar un error HTTP conocido y qué debe ocultar un error inesperado?

Comprobar razonamiento

Una HttpException conserva su estado y mensaje. Un fallo inesperado responde 500 con un mensaje genérico; su detalle técnico se registra en el servidor.

Un Exception Filter intercepta una excepción de la petición y construye la respuesta HTTP. Es un protocolo de atención: distintas causas, el mismo formato para comunicar qué pasó, cuándo y en qué ruta.

01

Distinguir la excepción

@Catch() sin argumentos puede atender cualquier excepción. instanceof HttpException distingue las excepciones HTTP conocidas de otros fallos.

02

Separar respuesta y diagnóstico

El cliente recibe statusCode, timestamp, path y message. El bloque de errores inesperados registra el detalle con console.error y usa un mensaje genérico.

Ver http-exception.filter.ts completoArchivo: http-exception.filter.ts · Ubicación: src/common/filters/ · Crear · TypeScript

import {
  ArgumentsHost,
  Catch,
  ExceptionFilter,
  HttpException,
  HttpStatus,
} from '@nestjs/common';
import { Request, Response } from 'express';

@Catch()
export class HttpExceptionFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    const esExcepcionHttp = exception instanceof HttpException;
    const statusCode = esExcepcionHttp
      ? exception.getStatus()
      : HttpStatus.INTERNAL_SERVER_ERROR;

    let mensaje: string | string[] = 'Error interno del servidor';
    if (esExcepcionHttp) {
      const cuerpo = exception.getResponse();
      mensaje = typeof cuerpo === 'string' ? cuerpo : (cuerpo as any).message;
    } else {
      console.error(exception);
    }

    response.status(statusCode).json({
      statusCode,
      timestamp: new Date().toISOString(),
      path: request.url,
      message: mensaje,
    });
  }
}

import {
  ArgumentsHost,
  Catch,
  ExceptionFilter,
  HttpStatus,
} from '@nestjs/common';
import { Request, Response } from 'express';
import { Prisma } from '../../generated/prisma/client';

@Catch(Prisma.PrismaClientKnownRequestError)
export class PrismaExceptionFilter implements ExceptionFilter {
  catch(exception: Prisma.PrismaClientKnownRequestError, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    const base = {
      timestamp: new Date().toISOString(),
      path: request.url,
    };

    switch (exception.code) {
      case 'P2025':
        return response.status(HttpStatus.NOT_FOUND).json({
          statusCode: HttpStatus.NOT_FOUND,
          ...base,
          message: 'El recurso solicitado no existe',
        });
      case 'P2002':
        return response.status(HttpStatus.CONFLICT).json({
          statusCode: HttpStatus.CONFLICT,
          ...base,
          message: 'Ya existe un registro con ese valor único',
        });
      case 'P2003':
        return response.status(HttpStatus.BAD_REQUEST).json({
          statusCode: HttpStatus.BAD_REQUEST,
          ...base,
          message: 'La relación referenciada no existe',
        });
      default:
        return response.status(HttpStatus.INTERNAL_SERVER_ERROR).json({
          statusCode: HttpStatus.INTERNAL_SERVER_ERROR,
          ...base,
          message: 'Error interno de base de datos',
        });
    }
  }
}

14 · Documentar el contrato

Una definición reutilizable

La implementación responde; OpenAPI describe esa respuesta.

Compara responsabilidades

¿ErrorRespuestaDto necesita class-validator para que Swagger muestre los errores?

Comprobar razonamiento

No. Este DTO describe una salida; no valida una entrada. @ApiProperty documenta las propiedades y @ApiResponse referencia la clase.

@nestjs/swagger genera la especificación OpenAPI desde el código y sus decoradores. Es el manual interactivo en /docs: mantenerlo correcto requiere conservar la correspondencia entre documentación y comportamiento.

01

Crea primero ErrorRespuestaDto. statusCode es numérico; timestamp y path son texto; message puede contener uno o varios mensajes.

export class ErrorRespuestaDto {

import {
  Body,
  Controller,
  Delete,
  Get,
  Param,
  ParseIntPipe,
  Patch,
  Post,
  Query,
  UseGuards,
} from '@nestjs/common';
import {
  ApiBearerAuth,
  ApiQuery,
  ApiResponse,
  ApiTags,
} from '@nestjs/swagger';
import { JwtAuthGuard } from '../auth/jwt-auth.guard';
import { RolesGuard } from '../auth/roles.guard';
import { Roles } from '../auth/roles.decorator';
import { Rol } from '../generated/prisma/client';
import { UsuarioActual } from '../auth/usuario-actual.decorator';
import { TransaccionesService } from './transacciones.service';
import { CrearTransaccionDto } from './dto/crear-transaccion.dto';
import { ActualizarTransaccionDto } from './dto/actualizar-transaccion.dto';
import { FiltrarTransaccionesDto } from './dto/filtrar-transacciones.dto';
import { TipoTransaccionDto } from './dto/crear-transaccion.dto';
import { ErrorRespuestaDto } from '../common/dto/error-respuesta.dto';

@ApiTags('transacciones')
@ApiBearerAuth()
@UseGuards(JwtAuthGuard)
@ApiResponse({ status: 401, description: 'No autenticado', type: ErrorRespuestaDto })
@Controller('transacciones')
export class TransaccionesController {
  constructor(private readonly transaccionesService: TransaccionesService) {}

  @Post()
  crear(
    @Body() dto: CrearTransaccionDto,
    @UsuarioActual() usuario: { id: number },
  ) {
    return this.transaccionesService.crear(dto, usuario.id);
  }

  @Get()
  @ApiQuery({ name: 'tipo', required: false, enum: TipoTransaccionDto })
  @ApiQuery({ name: 'desde', required: false, example: '2026-01-01' })
  @ApiQuery({ name: 'hasta', required: false, example: '2026-01-31' })
  @ApiQuery({ name: 'pagina', required: false, example: 1 })
  @ApiQuery({ name: 'limite', required: false, example: 10 })
  @ApiResponse({ status: 400, description: 'Filtros inválidos', type: ErrorRespuestaDto })
  obtenerMias(
    @Query() filtros: FiltrarTransaccionesDto,
    @UsuarioActual() usuario: { id: number },
  ) {
    return this.transaccionesService.obtenerMias(usuario.id, filtros);
  }

  @Get('admin/todas')
  @UseGuards(RolesGuard)
  @Roles([Rol.ADMIN])
  obtenerTodasAdmin() {
    return this.transaccionesService.obtenerTodasAdmin();
  }

  @Get(':id')
  obtenerUna(
    @Param('id', ParseIntPipe) id: number,
    @UsuarioActual() usuario: { id: number },
  ) {
    return this.transaccionesService.obtenerUna(id, usuario.id);
  }

  @Patch(':id')
  actualizar(
    @Param('id', ParseIntPipe) id: number,
    @Body() dto: ActualizarTransaccionDto,
    @UsuarioActual() usuario: { id: number },
  ) {
    return this.transaccionesService.actualizar(id, dto, usuario.id);
  }

  @Delete(':id')
  eliminar(
    @Param('id', ParseIntPipe) id: number,
    @UsuarioActual() usuario: { id: number },
  ) {
    return this.transaccionesService.eliminar(id, usuario.id);
  }
}

16 · Qué cambió

Un historial que se puede integrar

Devolver registros ya no basta: ahora la API expresa sus reglas y sus errores.

  • Problema resuelto: el historial ya permite consultas acotadas; las respuestas de error comparten una estructura.
  • Construimos: filtros y paginación por propietario, validación de rango, filtros de excepciones coordinados y documentación del contrato.
  • Ahora puedes: verificar consultas válidas, interpretar rechazos y revisar una ampliación administrativa generada con IA.

Tres ideas para conservar

1. Valida en la frontera. Transforma y comprueba antes del negocio.

2. Coordina el contrato. Cada filtro que responde debe cumplirlo.

3. Documenta lo que ocurre. El esquema y las pruebas deben corresponder al comportamiento.
